02 / HOW I BUILD
Working method

Problem first. Polish after proof.

The visual finish matters, but only after the workflow makes sense. I build in short loops: understand the problem, ship something usable, test the weak points, then refine.

01 / DEFINE

Find the real friction

Start with the frustrating moment the user actually experiences, not a feature wishlist.

02 / BUILD

Make a working version

Get the flow into a usable product quickly enough to learn what is wrong.

03 / TEST

Break the weak points

Use real devices, awkward states and edge cases instead of testing only the happy path.

04 / REFINE

Make it feel obvious

Remove unnecessary steps, improve feedback and make the useful action easier to reach.
